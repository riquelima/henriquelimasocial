01 / 06

A confusão comum: instalar ferramentas sem definir método

Quando alguém começa a usar o Claude Code ou qualquer agente autônomo no terminal, o primeiro impulso costuma ser instalar o maior número possível de servidores MCP. Conecta-se o GitHub, o PostgreSQL, o Slack, ferramentas de busca e automação de navegador.

Em poucos minutos, a sessão acumula 15 ou 20 ferramentas ativas. O resultado prático é o oposto do esperado: a cada mensagem enviada, o modelo precisa processar dezenas de esquemas JSON no prompt de sistema para manter essas ferramentas registradas. O consumo de tokens sobe rapidamente antes mesmo da escrita da primeira linha de código útil.

Ter muitas ferramentas à disposição sem um procedimento definido faz o modelo se perder. Ele tenta adivinhar a ordem dos comandos, executa alterações sem rodar testes prévios, ignora as regras arquiteturais do repositório e escreve código desalinhado com o time.

A regra prática:

Um MCP fornece o canal de comunicação com o mundo externo (a ferramenta). Uma Skill fornece o procedimento, a sequência de passos e os critérios de validação (o método). Ferramenta sem método produz código desorganizado.

02 / 06

O que é um MCP (Model Context Protocol) na prática

O Model Context Protocol é um padrão aberto criado pela Anthropic para padronizar a comunicação entre modelos de linguagem e sistemas externos via JSON-RPC.

Pense no MCP como um adaptador de tomada universal. Quando você conecta um servidor MCP de PostgreSQL, por exemplo, o Claude passa a enxergar ferramentas específicas como query, list_tables e describe_table. O MCP entrega as mãos e os olhos para o modelo interagir com bancos, APIs, navegadores e arquivos remotos.

As características fundamentais de um MCP:

  • Comunicação cliente-servidor: O servidor roda em segundo plano (via stdio ou SSE) e expõe schemas de ferramentas e recursos.
  • Custo constante de contexto: Cada ferramenta declarada no MCP injeta sua definição JSON no system prompt da conversa, consumindo tokens em todas as interações.
  • Ausência de heurística própria: O MCP não sabe se o seu projeto usa TypeScript estrito, não sabe se a migration deve rodar antes ou depois dos testes e não conhece a regra de negócio da sua empresa. Ele apenas executa o comando solicitado.
03 / 06

O que é uma Skill e por que ela consome zero tokens em repouso

Uma Skill é um procedimento técnico reutilizável, empacotado em uma pasta que contém um arquivo SKILL.md com metadados YAML e instruções detalhadas.

O mecanismo de funcionamento das Skills no Claude Code é muito eficiente em termos de consumo de contexto. No início de uma sessão, o Claude não lê o arquivo inteiro da skill. Ele lê apenas o cabeçalho YAML, que contém o nome da skill e uma descrição curta de duas ou três linhas explicando quando utilizá-la.

Isso significa que você pode manter 50 ou 100 skills configuradas na sua máquina sem pagar quase nada em tokens no prompt inicial. O arquivo completo da skill só entra no contexto no momento em que você faz uma pergunta ou dá um comando relacionado àquele assunto.

Exemplo de estrutura de um SKILL.md
---
name: code-review
description: |
  Audita pull requests e diffs de código contra padrões de arquitetura,
  segurança de dados e boas práticas de tipagem do time.
---

# Procedimento de Code Review

Quando solicitado para revisar código ou antes de aprovar um PR:
1. Obtenha o diff do branch usando o comando git apropriado.
2. Verifique se foram adicionados testes cobrindo as novas funções.
3. Cheque ausência de chamadas síncronas bloqueantes em rotas HTTP.
4. Identifique variáveis sem tipagem estrita no TypeScript.
5. Emita o relatório estruturado em três níveis: Bloqueante, Alerta e Sugestão.

Além do arquivo Markdown, uma Skill pode conter uma pasta scripts/ com utilitários em Python, Node.js ou Bash. Esses scripts rodam localmente no terminal sem precisar passar pelo modelo de linguagem, economizando tokens e garantindo respostas determinísticas.

04 / 06

Comparativo direto: MCP vs Skill

Para eliminar qualquer dúvida prática na hora de estruturar seus agentes, observe as diferenças fundamentais de arquitetura:

Critério MCP (Model Context Protocol) Skill (Procedimento Sob Demanda)
Papel Principal Fornecer conexões, APIs e ferramentas externas (as mãos). Ensinar métodos, regras de negócio e ordem de execução (o cérebro).
Consumo de Tokens Contínuo. Os schemas JSON das ferramentas ocupam espaço no system prompt o tempo todo. Zero em repouso. Apenas 1-2 linhas de descrição ficam na memória até a skill ser chamada.
Momento de Carga Na inicialização da sessão do Claude Code. Sob demanda, quando o prompt do usuário coincide com o objetivo da skill.
Estrutura de Código Servidor executável em Node.js, Python ou Go implementando a spec MCP. Pasta local com arquivo SKILL.md, checklists e scripts opcionais.
Exemplos Típicos Acessar banco Supabase, disparar mensagens no Slack, rodar Playwright. Auditar PRs, conduzir refatoração com TDD, formatar changelog, revisar cópia.
05 / 06

Onde cada uma brilha: regras práticas de decisão

Para não ter dúvidas no dia a dia, use a seguinte divisão de trabalho:

Use MCP quando precisar de:

Ações no Mundo Exterior

  • Executar queries SQL e migrações de banco em produção ou staging.
  • Consultar e abrir pull requests na API do GitHub ou GitLab.
  • Controlar uma janela de navegador para testes end-to-end ou scraping.
  • Conectar com ferramentas de design como Figma ou Canva.
  • Enviar alertas para canais do Slack ou Discord.
Use Skills quando precisar de:

Método e Disciplina de Engenharia

  • Padronizar o checklist de Code Review da equipe.
  • Exigir ciclo TDD estrito (escrever teste que falha antes de codificar a solução).
  • Executar refatorações seguras com verificação de raio de impacto.
  • Escrever documentação técnica e decisões de arquitetura (ADRs).
  • Revisar textos e artigos eliminando clichês e vícios de escrita de IA.
06 / 06

A combinação definitiva: Skills comandando MCPs

A maior evolução na produtividade de um desenvolvedor acontece quando ele para de tratar MCP e Skill como alternativas concorrentes e passa a combiná-los.

No fluxo combinado, a Skill define a ordem do processo de pensamento e aciona as ferramentas do MCP exatamente quando necessário. O MCP fornece os dados brutos e os métodos de envio, enquanto a Skill garante que as regras de negócio e de qualidade sejam cumpridas.

Exemplo prático de um fluxo combinado:

  1. Você pede ao Claude: "Revise o PR #42 contra nossos padrões de segurança."
  2. O Claude ativa a Skill security-review. A Skill é carregada na memória com suas regras e checklists.
  3. A Skill instrui o Claude a chamar a ferramenta get_pull_request_diff do MCP do GitHub.
  4. O Claude recebe o diff e roda a auditoria prescrita na Skill (verificação de injeção SQL, checagem de sanitização de inputs e tratamento de erros).
  5. A Skill executa um script local para validar se há novas variáveis de ambiente sem documentação no .env.example.
  6. Ao concluir a análise, a Skill instrui o Claude a chamar a ferramenta create_pull_request_comment do MCP do GitHub para postar o feedback formatado diretamente na linha correta.

Esse fluxo não funcionaria apenas com o MCP (o modelo postaria comentários genéricos sem critério fixo) e não funcionaria apenas com a Skill (o modelo não teria acesso à API do GitHub). A união das duas peças cria um pipeline confiável e reproduzível no terminal.

- Valide se não há vazamento de credenciais ou dados sensíveis
EOF

03 / 04 CONFIGURAÇÃO // INSTALAÇÃO

Como instalar o MCP no Claude Code ou Cursor

A instalação do Model Context Protocol leva menos de três minutos e não exige banco de dados externo ou servidor dedicado:

Etapas da instalação:
  • 01
    Extrair os arquivos: Descompacte a pasta IntelektusLandingPages no seu computador (por exemplo, em ~/mcp-landing-pages).
  • 02
    Instalar pacotes: Abra o terminal na pasta extraída e rode npm install.
  • 03
    Adicionar ao Claude Code: Registre o servidor local rodando o comando:
    claude mcp add intelektus-landing-pages -- node /caminho/para/profitize-templates-mcp/src/index.js
  • 04
    Ou usar no Cursor: No arquivo claude_desktop_config.json ou nas configurações de MCP do Cursor, aponte para o executável gerado. O agente passa a listar os templates automaticamente.
Exemplos de pedidos no terminal do Claude:
"Liste os modelos de landing page disponíveis para hamburgueria artesanal."
"Aplique o template Brasa Smash Burger trocando a logo para Ogro Burger e ajustando o menu."
"Insira um formulário animado com tema escuro para captar leads de clínica de estética."
